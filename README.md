# Dayflow

個人用のタスク、予定、メモ、ポモドーロを一箇所で扱う静的ダッシュボードです。

## 機能

- タスク管理（優先度、期限、繰り返し、サブタスク、通知）
- カレンダー（日付選択、予定の追加・編集・確認付き削除、時刻順表示、タスク期限、開始日〜終了日の期間予定、繰り返し予定、予定の通知、色分け）
- クイックメモ、ポモドーロ（一時停止・再開、画面移動中の完了記録）
- ブックマーク管理
- 電卓と単位変換
- QRコード生成（日本語・絵文字・空白・改行、画像保存、誤り訂正・配色・サイズ設定）
- 文章の差分比較
- スマートフォンのホーム画面への追加・インストール案内

データの保存と各ツールの処理はブラウザ内で行います。QRコード生成には、MITライセンスの qrcode-generator 2.0.4 を同梱しています。取得時に従来のSRIハッシュとの一致を検証済みです。入力はUTF-8で処理し、QR生成に外部CDNへの接続は不要です。容量超過や読み取りにくい配色では保存を止め、密度の高いQRは読み取りに必要な画像サイズへ自動で拡大します。

## スマートフォンで使う

公開サイトの最上部にある「追加方法を見る」から、端末に合った手順を確認できます。対応ブラウザでは「インストール」から直接進めます。iPhone/iPadは共有メニューの「ホーム画面に追加」を選び、表示される場合は「Webアプリとして開く」をオンにします。追加後のアプリとして起動している間は案内を表示しません。

iPhone/iPadでは、ブラウザ内の保存データが追加したアプリへ引き継がれない場合があります。既存データがあるときは「TASKS」からバックアップを保存し、追加したアプリの「復元」で読み込んでください。

一度開いた後は、電波が無いときも保存済みのファイルで起動します（Service Worker）。オンラインでは毎回サーバーへ更新を確認するため、公開した変更はすぐに反映されます。オフライン中はGoogleフォントの代わりに端末の標準フォントで表示します。

## カレンダーの予定

- **期間**: 開始日〜終了日を1件の予定として登録します。時刻は開始日に適用されます。
- **繰り返し**: 毎日・毎週・毎月・毎年から選び、繰り返しの終了日も指定できます。毎月31日・毎年2月29日のように、その日が無い月や年は飛ばします。期間つきの予定を繰り返す場合は、次の回と重ならない長さ（毎週なら7日以内など）に限ります。編集はすべての回に反映され、カレンダー上の回から開くと「この回だけ削除」もできます。
- **通知**: 開始時刻〜1日前から選びます。終日の予定は当日9:00を基準にします。通知はDAYFLOWを開いている間に届き、通知時刻から1時間以上経った通知はまとめて出しません。予定を保存したときにブラウザへ通知の許可を求めます。
- **色**: 青・緑・紫・ピンク・グレーから選べます。「自動」は1日だけの予定を青、期間の予定を緑で表示します。

## データの保護

繰り返しタスクは完了チェックで複製せず、次回日に同じタスクが未完了へ戻ります。月次の基準日は保持するため、31日指定は2月末を経ても翌月31日に戻ります。サブタスクを含む編集は「保存」でまとめて確定し、「キャンセル」で破棄できます。

タスク画面からJSONバックアップの保存・復元ができます。復元前に各項目の形式を検証し、確認後に置き換えます。保存データの破損を検出した場合は、元データを `dayflow-v2-recovery-日時` キーへ退避してから読み込み可能な内容を復旧します。保存できない場合も画面に警告します。

## ローカル確認とテスト

`index.html` をブラウザで開くか、このフォルダで `python -m http.server 8765 --bind 127.0.0.1` を実行し `http://127.0.0.1:8765/` を開きます。

Node.js標準機能だけで回帰テストを実行できます。

```sh
node --test tests/app.test.cjs tests/calendar.test.cjs tests/schedule.test.cjs tests/sw.test.cjs tests/qr.test.cjs tests/tasks.test.cjs tests/install.test.cjs
```

予定の日付計算（繰り返し・通知の時刻）は `schedule.js` にまとめ、`tests/schedule.test.cjs` で確認します。`tests/sw.test.cjs` は、オフライン用に保存するファイル一覧に画面が読み込むファイルの漏れが無いことも検証します。アプリにファイルを追加したときは `sw.js` の `APP_FILES` にも追加してください。

QRのテストでは、実際に描画されたQRのデータを独立に読み戻し、元の日本語・絵文字・空白・改行と一致することを確認します。

Playwrightを利用できる環境では `node tests/browser-smoke.cjs` で実ブラウザの操作も確認できます。必要に応じて `NODE_PATH` に既存のPlaywrightの場所、`DAYFLOW_BROWSER_PATH` にブラウザ実行ファイルのパスを指定してください。一時プロファイルで動作し、外部通信を遮断して検証します。

## GitHub Pages への公開

1. このフォルダをGitHubリポジトリにpushします。既存リポジトリなら、既定ブランチは `main` にしてください。
2. GitHubのリポジトリで **Settings → Pages** を開き、**Build and deployment** の **Source** を **GitHub Actions** に変更します。
3. `main` へのpush後、**Actions** の「Deploy static site to GitHub Pages」が完了すると、PagesのURLで公開されます。

データはブラウザのLocal Storageにのみ保存されます。同じブラウザ・端末では保持されますが、端末間での同期はしません。
